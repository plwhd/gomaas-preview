个人网站 UI 规范与现行基线

版本：1.3 · 2026-10-04。适用：李鹏飞个人网站。整体视觉基线依据源码快照 7ba7ef535b4b99d7be16f95286b812bcbf0bf0df，文章列表采用用户已认可的 b46ce7c。当前公开版本 ce37ac1：文章列表V1参数保持，生活与杂记V2及XX栏目文字已正式发布。

目的与状态

用户希望以后按统一规范调整 UI，避免逐个元素凭感觉反复修改。本文件把已经确认的方向、实际参数与例外集中起来，供后续任务使用。规范最初仅整理文档；10-04用户认可文章列表V1并明确要求发布，第三、四节已更新为正式参数，第六节保留旧新对照与依据。

规范帮助同类页面保持一致，但不保证当前每个参数都最合适。用户指出问题后，应结合页面用途和真实内容重新判断；完成整组审阅后更新基线，不能用旧参数否定新反馈。

一、参考来源与边界

  • 主视觉参考：jmitch.com：窄栏单列、充分留白、圆形头像、标题/正文/等宽辅助信息分工、细线分隔和克制的浅色背景。出处见 DECISIONS 的初版参考与2026-09-19约束。本文件中的数值是本站源码的现行值，不声称全部是参考站的像素级测量；本次没有完成新的参考站浏览器测量。
  • 文章信息组织参考：yinxulai.com/articles：列表进入详情、详情顶部返回列表、标题/摘要/日期组织。文章列表与正文仍使用本站视觉，不套用其整套视觉。
  • 唯一已确认的独立视觉例外：网页演示模块参考 yinxulai 的 Slide 示例。参数测量记录见 DECISIONS 的“2026-10-03 · 演示展示以实测参考为准”；不能反向改变首页或文章样式。
  • 其他网站只作为有具体目的的对照；先说明要借鉴什么，不因看到一个新参考就替换原体系。不复制他人的文案、头像或许可未确认的源码和资产。

二、稳定原则

  1. 网站主要服务于个人介绍、职业方向、真实实践和学习分享；首页仍承担个人介绍，文章栏目容纳长文与深度内容，也保留演示条目入口。
  2. 保持窄栏单列。没有明确新需求，不改为卡片墙、多栏或营销落地页，不为视觉规范引入框架、组件库或付费服务。
  3. 层级按内容角色定义：页面名称、条目标题、摘要、日期。相同 HTML 标签不等于必须相同视觉；新规则应覆盖同类元素，不逐条为单篇标题做特殊处理。
  4. 中文排版与真实长标题单独检查；不能仅凭英文参考或截图缩放推算最终字号。短标题看起来合适，不代表长标题也成立。
  5. 保留可操作反馈：链接悬浮下划线、键盘焦点、当前导航标识。七牛云只允许名称链接，logo和职位不扩为点击区域。
  6. 保留用户已经确认的首次 B 展翼图标和页脚间距。页脚保留版权、语言切换与社交链接，不恢复域名或城市。

五、演示模块例外

dist/assets/slides.css 是演示的局部基线，不套普通网页标题。已确认：40×40px控制按钮、8px间距、左/下24px偏移；白色/深色画布；独立封面/章节/正文比例；逐页计时。精确字号、clamp、行高和网格按现有CSS及测量记录核对，不在此重复建立第二份全部参数表。

手机只提示使用电脑浏览，不自行发展为手机PPT阅读系统。入口仍在文章列表，不新增顶部导航入口。

六、文章列表的历史分析与已确认 V1

历史事实（10-03）：此前用户要求栏目标题和条目标题字号与首页“为什么选择云服务销售”一致，当时23px/21px符合该决定。随后截图提出新的视觉反馈，不能直接称此前实现错误；10-04用户已认可下面V1并授权正式发布。

判断：栏目与条目字号相同、长中文标题的600字重与负字距叠加，以及首页式留白用于列表后形成的较低信息密度，需要作为一组评估。每个现象并非独立缺陷，不应逐个盲改。

候选：保留栏目23px，将栏目字重700改为600；条目试20–21px/500、中文接近正常字距；配合小幅收紧标题至摘要及条目间距。上述候选来自本站用途判断，不是从jmitch/yinxulai测得的值。上一轮提供的Sara文章页只是信息层级对照，不成为新的全站视觉参考。

状态：10-04用户先要求一版预览，后明确“符合预期，请更新到正式版”。V1已发布，第三、四节已替换为正式参数；以下旧新对照保留版本依据。

七、后续UI修改流程与停止条件

  1. 先读本文件、AGENTS、CURRENT，检查git status；确认用户是在分析、要预览还是要发布。保护无关改动。
  2. 先核实加载版本、缓存、实际字体与问题。先指出受影响的内容角色及已有决定，不从一句反馈推导全站重设计。
  3. 给出一组相互协调的调整，明确范围与不动项；优先复用现有CSS角色。只讨论时不改页面。候选参数与已确认基线分别记录。
  4. 修改后用真实内容验证：首页、列表、正文及演示按受影响范围检查；通常至少1280px桌面和390px手机，涉及窄屏/折行时补320px；受影响的中文/英文、长标题、链接悬浮和键盘焦点一起看。演示按其独立电脑要求检查，手机检查提示即可。
  5. 页面代码修改运行npm run check和git diff --check，核对新增中文字形覆盖；对文档整理只检查文档差异与链接，不重复构建和发布。
  6. 检查通过后按本项目规则提交明确文件，更新规范的当前值及决定依据。发布单独依据用户授权，记录源/公开提交和回退。已有上一批发布授权不扩为任意下一批发布。
  7. 达到当前验收结果后停止。不为“看起来更统一”顺带改头像、图标、正文、页脚或域名；新发现记录后另行判断。

本阶段不新建组件平台、设计系统工程或规范演示站；不自动把CSS迁移为tokens。之后若多处重复参数确实妨碍维护，再判断是否有必要做代码层面的集中管理。

配套写作规范

文案编辑同时遵循写作与语气规范。UI规范管理排版，写作规范管理表达与内容职责；视觉调整不自动授权改写观点，精简文案不自动调整字号和间距。
