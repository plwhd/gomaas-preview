理解大模型 API：服务链路、计费与选择

发布于 2026.10.10版本：V2AI 辅助：GPT

关键词：大模型 API　·　Token 计费　·　计费倍率　·　提示词缓存　·　容量与速度

This article is available in Chinese.

大模型 API 页面上的信息可以分成四类：服务来源、计费规则、容量与速度、生成参数。下面分别解释。文中的价格和倍率均为计算示例，不是供应商实时报价。

服务链路：模型是谁的，请求由谁处理

推理 是模型接收输入并生成结果的过程； 训练 是学习数据、调整模型参数的过程。调用 API 通常是在使用推理服务。

角色 提供什么 例子或说明
模型研发方 开发和训练模型 OpenAI、Anthropic、Google
推理服务商 部署模型，提供计算资源和调用服务 可以是研发方，也可以是部署开放权重模型的其他公司
云平台 提供云基础设施或托管模型服务 通过自己的云账号、接口和账单提供服务
聚合平台 在一个入口接入多个模型或服务渠道 统一接口、余额和模型列表，底层请求仍需交给相应服务处理

这些角色可以重叠。通过聚合平台调用时，常见链路是：

你的应用 → 聚合平台 → 上游模型服务 → 返回结果。

“词元工厂”不是通用技术术语，可能是某个平台对推理服务或服务渠道的命名，应看该平台的定义。模型名称本身不能说明服务渠道；“官方模型”“官方直连”和“官方授权”也分别涉及模型来源、连接路径和合作关系。

API 接入与 Token

API（Application Programming Interface，应用程序编程接口） 是程序调用服务的入口。接入模型时常见三个字段：

字段 含义
Base URL 接口地址，决定请求发往哪个服务
API Key 调用凭据，用于身份验证和权限控制
Model ID 模型标识，决定调用哪个模型或平台定义的渠道

Token（词元） 是模型处理文本的基本单位。它可能是一个词、词的一部分或一个字符；不能固定换算成几个汉字或单词。图片、音频等输入的计量方式还取决于模型。账户中的“访问令牌”是凭据，与计费用的词元不是同一个概念。Google 的 Token 说明

  • 输入 Token ：发送给模型的内容，包括问题、系统指令、历史对话、资料和工具返回的内容。
  • 输出 Token ：模型生成的内容；某些推理模型还会计入未直接展示的思考用量，按模型计费规则处理。
  • K / M ：通常分别表示一千 / 一百万。价格为 0.02 元/K，等于 20 元/M。

聊天产品的订阅额度与 API 余额是不同的计费项目，不能默认互通。

费用：单价、用量与积分

没有缓存、工具等额外费用时，按 Token 计费的基础公式是：

费用 = 输入 Token 数 ÷ 1,000,000 × 输入单价 + 输出 Token 数 ÷ 1,000,000 × 输出单价。

这里的单价单位统一为“元/百万 Token”。假设输入为 20 元/M，输出为 100 元/M，一次调用输入 10,000 Token、输出 2,000 Token：

10,000 ÷ 1,000,000 × 20 + 2,000 ÷ 1,000,000 × 100 = 0.40 元 。

如果平台使用积分结算，先将积分单价换算成人民币。假设 35 元购买 1,000 积分，模型输入价格为 420 积分/M：

420 ×（35 ÷ 1,000）= 14.70 元/M 。

倍率：相对于哪个基准乘多少

倍率是计费系数。 要知道实际价格，必须知道它乘在哪个基准上。以 New API 的倍率设置为例，常见三种倍率分别负责：

名称 含义 示例
模型倍率 该模型的输入计费相对于平台基准的系数 基准为 10 元/M，模型倍率为 2，输入单价就是 20 元/M
输出倍率（补全倍率） 输出相对于同一模型输入的计费系数 输入为 20 元/M，输出倍率为 5，输出单价就是 100 元/M
分组倍率 用户所在分组的计费系数，作用于输入和输出 倍率为 0.8，按上述价格的八折结算

在这个简化例子中，平台基准已经换算为人民币：

输入单价 = 基准单价 × 模型倍率 × 分组倍率。

输出单价 = 基准单价 × 模型倍率 × 输出倍率 × 分组倍率。

使用表中的数字，最终输入为 16 元/M ，输出为 80 元/M 。输入一百万 Token、输出二十万 Token，费用是：

1 × 16 + 0.2 × 80 = 32 元 。

因此，“模型倍率为 2”不等于“官方价格的两倍”，除非平台明确以官方价格为基准。如果页面已经显示经过这些倍率计算后的最终输入、输出单价，就直接使用该单价， 不要再乘一遍倍率 。积分、缓存或按次收费还需分别按平台规则计算。

提示词缓存：重复输入怎样收费

提示词缓存（Prompt Caching） 复用符合条件的输入前缀的计算结果，例如多次请求中相同的系统指令或资料；模型仍会生成新的回答，不是直接复制上次的答案。

计费项 含义
普通输入 没有命中缓存、按普通输入价格处理的内容
缓存写入 创建缓存的内容；部分服务另设写入价格
缓存读取 / 命中 复用已有缓存的内容，通常有单独的读取价格
TTL（Time to Live） 缓存有效期；过期后不能继续按原缓存读取

缓存规则因服务而异。例如 Claude 提供不同有效期的缓存，其写入和读取分别计价，命中还需满足内容一致、有效期和最小长度等条件。Claude 的缓存说明

假设普通输入为 20 元/M，缓存读取为 2 元/M。一次请求有 10,000 输入 Token，其中 9,000 命中缓存、1,000 为普通输入，则输入费用为：

9,000 ÷ 1,000,000 × 2 + 1,000 ÷ 1,000,000 × 20 = 0.038 元 。

这只计算本次输入费用，不包含输出费用或此前创建缓存的写入费用。实际账单应按各类用量分别乘对应单价，再求和。

容量与速度：分别看哪些指标

指标 含义 主要回答的问题
TPM Tokens Per Minute，每分钟 Token 限额 一分钟内允许处理多少 Token？
RPM Requests Per Minute，每分钟请求限额 一分钟内允许调用多少次？
并发数 同时进行的请求数量 能同时处理多少个任务？
TTFT Time to First Token，首个 Token 返回时间 提交后多久开始看到生成内容？
生成速度 通常以 tokens/s 表示 开始生成后，每秒返回多少 Token？

TPM 和 RPM 描述额度，TTFT 和生成速度描述响应表现。额度较高不代表单次回答更快。

有些服务将输入和输出限额分别标为 ITPM / OTPM ；缓存用量是否计入限额也按服务规则确定。Claude 的限流说明

若平台写“TPM 5000W”，且 W 表示“万”，就是每分钟五千万 Token。还需确认这是你的账户额度，还是平台整体容量。

生成参数：能处理多少、如何生成

参数 含义 阅读时关注什么
上下文窗口（Context Window） 一次请求可容纳的上下文规模 常需同时容纳输入和生成内容；具体口径按模型文档
最大输出（Max Output Tokens） 单次允许生成的 Token 上限 是长度上限，不是保证会生成这么多
温度（Temperature） 调整生成的随机性 较高通常更发散；不是准确率或速度的评分
推理强度（Reasoning Effort） 控制模型的推理投入 仅部分模型支持；可能影响用量和等待时间
流式输出（Streaming） 在生成过程中逐步返回内容 可以边生成边显示，不必等待完整回答

聚合平台、网关与工具调用

术语 含义
聚合平台 将多个模型服务接入同一入口，统一调用和结算
网关（Gateway / Proxy） 请求经过的中间服务，负责认证、额度控制、日志或转发等
路由（Routing） 按模型、价格、可用性等规则选择请求渠道
故障回退（Fallback） 当前模型或渠道失败时，尝试备用模型或渠道
工具调用（Tool Calling） 模型生成工具名称和参数，由应用执行工具，再将结果交给模型
接口兼容 支持某种接口格式，使已有代码较容易接入；不说明底层模型来自谁

例如，Google 的模型可以通过兼容 OpenAI 接口的方式调用，底层仍然是 Google 的模型服务。Google 的接口兼容说明

LiteLLM 等网关软件可以统一接入多个服务。在自己的电脑或服务器运行网关，只表示中间服务在本地运行；如果它转发到远程模型，推理仍由远程服务完成。LiteLLM 的网关说明
